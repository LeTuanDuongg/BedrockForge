# Android Bedrock mod-loader architecture comparison

**Target:** Minecraft Bedrock 1.26.52.3, ARM64; Samsung Galaxy M51, Android 12

**Decision:** No host is currently verified as both authorized and compatible with this target. Keep HybridMCPE's runtime and ABI; gate the next integration on an authorized host that can run this exact engine.

## Findings

| Project | How the game runs | Mod-facing surface | Evidence and limits for this target |
|---|---|---|---|
| LeviLauncher / LeviLaunchroid | A launcher-owned Android process embeds Minecraft's Java activity classes. `GamePackageManager` obtains the installed package context and APK paths, prepares the asset manager and native libraries, then loads the engine libraries in that host process. This avoids installing a re-signed clone, but it is a separate host implementation, not a drop-in loader for an existing app. | Preloader provides native mod lifecycle, configuration, UI/input and low-level hook facilities. Hook rules are version-specific; they are not stable gameplay/container APIs. | v1.5.27 documents Android 9+ and ARM64 requirements, which fit the M51's OS/ABI. Release notes specifically mention MC 1.26.50; they do not verify 1.26.52.3 or the M51. The evaluated host uses `StubStore` whose license checks unconditionally pass, and `NativeImageGuard` may rewrite cached engine libraries. Do not use this host as evaluated or copy those behaviors. LeviLaunchroid source is Apache-2.0; Minecraft binaries and terms remain separate. |
| Inner Core / Horizon | Horizon owns a separate game runtime and separate settings/world folders. Its documented install flow requires a purchased/downloaded game. | Documented JavaScript/TypeScript, Java and C++ integration; staged mod lifecycle; callbacks; blocks/items; block-associated `TileEntity`; `ItemContainer` transactions and slot persistence; mod UI windows bound to containers; mod dependencies and packs. | Excellent API and behavior reference for a future Iron Chest. The docs show custom container UI, not registration into vanilla `ChestScreen`/`ScreenController`. Horizon lists an Android 12 build, but that only indicates OS support. The legacy engine history cites MCPE 1.11.4; no evidence found for 1.26.52.3, ARM64 on this device, or a compatible authorized runtime pack. The public toolchain's reuse license was not verified. |
| HybridMCPE | Current Android helper opens the installed Minecraft app; it does not host or load code into it. The modified-APK bootstrap route remains NO-GO. | Independent Mod ABI 1, native runtime, target fingerprint/layout checks, capability gates and a replaceable Preloader adapter. Gameplay capabilities remain disabled. | The adapter has since been pinned to Preloader commit `7ca94daedfa30d6d4c265fc9b591768e8dc1f5af`, the submodule used by Levi v1.5.24. It exports `PLGetModRegistration`; the host-facing C++ registration is isolated from HybridMCPE's C ABI. The `.levipack` still is not a validated game deployment route. |

## Recommendation and smallest valid test

Do not integrate LeviLauncher v1.5.27 as the host: the evaluated license path is incompatible with the requirement to preserve licensing behavior, its native-image behavior is unresolved, and the target engine version is not documented. Levi v1.5.24's exact Preloader submodule revision is now verified and the matching registration adapter exists, but its host still needs an authorized, integrity-safe configuration and exact target support before deployment.

Horizon is NO-GO as the 1.26.52.3 execution host: available official sources do not identify a runtime for this engine version or document a third-party native `.so` loading interface. Android 12 support alone does not establish engine compatibility. Keep its lifecycle, container and UI APIs as design references; reconsider hosting only when an authorized runtime explicitly supports 1.26.52.3 ARM64 and exposes a documented native-module interface.

Once that gate passes, the smallest end-to-end test is a diagnostic native mod with no engine calls: launch the authorized host, log PID and ABI, confirm the 1.26.52.3 engine mapping and existing fingerprint/layout checks, then run HybridMCPE load/enable/disable/unload and check the process remains stable. Keep the host's world storage separate and use a new disposable world only after the process test passes. Do not enable gameplay capabilities during this test.

## Reuse decision

- Keep HybridMCPE's Mod ABI, runtime, target profile and capability gates independent of either host.
- Reuse Levi's architecture and documented Preloader API as research references. No Levi or Preloader implementation was copied; the pinned Preloader tree in the current compatibility record had no license file, so redistribution remains out of scope until licensing is clarified.
- Use Inner Core's lifecycle, transaction, slot-saving and UI patterns as API references only. Do not copy its toolchain or claim vanilla chest-screen support without verified source and a target runtime.
- No source or runtime files were changed for this comparison. No app was installed, no game was launched, and no device or world data was modified.
